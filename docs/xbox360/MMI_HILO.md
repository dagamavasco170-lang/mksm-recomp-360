# PS2 MMI HI/LO transfer semantics

## Verified transfer operations

The EE Core Instruction Set Manual describes these four MMI operations as full 128-bit copies:

- **PMFHI rd**: copy HI[127:0] into GPR[rd].
- **PMFLO rd**: copy LO[127:0] into GPR[rd].
- **PMTHI rs**: copy GPR[rs][127:0] into HI[127:0].
- **PMTLO rs**: copy GPR[rs][127:0] into LO[127:0].

These are distinct 128-bit banks; writing one bank must not change the other.

Reference: [EE Core Instruction Set Manual, PMFHI/PMFLO/PMTHI/PMTLO sections](https://docs.alexrp.com/mips/ee_insns.pdf) (also mirrored at [studylib](https://studylib.net/doc/28989088/ee-insns)).

## Current implementation

`ps2_mmi_hilo_helpers.h` provides a shared, byte-order-independent `Vector128` and complete HI/LO bank storage, conversion to/from the desktop context's four 64-bit fields, and semantics for PMFHI/PMFLO/PMTHI/PMTLO/PMADDH. The desktop runtime wrappers and the Xbox generated ABI use the same helper semantics. PMADDH updates eight independent 32-bit accumulator lanes and returns the documented destination word ordering.

Host tests verify transfer round trips, bank independence, signed-halfword products, modulo-2^32 wraparound and every accumulator lane. A 9-instruction synthetic MIPS function is also generated by PS2Recomp and executed as emitted C++ against both the desktop runtime and Xenon ABI host shim. Both return `failures=00000000`.

**Still incomplete:** PHMADH/PMSUBH/PHMSBH, PMFHL/PMTHL variants, remaining packed multiply/divide operations, full decoder/runtime integration, timing/interlocks and game execution. The XEX from the latest passing CI is compile-validated but has not yet been rerun on physical Xenon hardware. Passing these focused tests is not evidence that a game can run.
